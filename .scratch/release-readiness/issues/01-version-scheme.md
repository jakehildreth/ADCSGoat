# Version scheme

Type: grilling
Status: resolved

## Question

Which single version identifies this release, applied consistently across source manifest, generated artifact manifest, changelog, Git tag, and Gallery package?

Current state is inconsistent: source manifest reads `2026.7.220804`, Gallery latest is `2026.7.221210`, the checklist's working target is `2026.8.121930`, and the latest Git tag is `0.4.1` — a SemVer tag on a CalVer project.

Sub-questions: does the Git tag scheme switch to CalVer to match (per Jake's standing CalVer standard), and what regenerates the `0.4.1`-style tag history story?

## Answer

1. **Tags switch to CalVer going forward.** Next tag is `yyyy.M.dHHmm`-style (e.g. `2026.8.161200`). The `0.x` tags remain as untouched history.
2. **The build's `-CalVer` parameter is the single source of truth.** It stamps the artifact manifest; the release process back-writes the same value into the source manifest, the changelog header, and the Git tag. One command, one version, everything downstream reads it.
3. **The changelog is regenerated by git-cliff at release time.** The two stale `[unreleased]` sections collapse into the new CalVer release header; the meta footer is corrected from "Semantic Versioning" to CalVer. Old `0.x` sections stay as history. `cliff.toml` needs no scheme change — `{{ version }}` renders from the tag.
4. **Emoji carve-out:** emojis are permitted in changelog group headers (🚀 🐛 etc.), an explicit exception to the no-emoji documentation standard. `cliff.toml` keeps them.
